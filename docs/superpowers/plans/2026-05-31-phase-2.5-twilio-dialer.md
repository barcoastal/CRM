# Phase 2.5: Real Telephony — Swap Mock for Twilio

**Goal:** Replace `MockTelephonyProvider` with a real Twilio Programmable Voice implementation so the existing dialer engine, session manager, disposition flow, and recording hooks become **actual phone calls**.

**Non-goals:** Predictive dialing pacing (keep Five9 for that), IVR menus, inbound call routing (Phase 6), call transcription (already scaffolded via `Transcript` model — plug in later), replacing Five9 for power-dial campaigns.

**Why Twilio over Telnyx for this phase:** the existing telephony interface is shaped for the Twilio SDK pattern (CallSid, status callbacks, Device.connect()). The provider abstraction makes swapping to Telnyx later a one-file change.

**Telephony architecture chosen:** Browser softphone (agent uses WebRTC in the dialer UI) → Twilio bridges → lead's phone. One Twilio call leg. Lower latency, better UX, no agent cell needed.

## Implementation order

1. **Provider stub** — `twilio-provider.ts` with all `TelephonyProvider` methods (`makeCall`, `endCall`, `getCallStatus`, `holdCall`, `resumeCall`, `muteCall`, `unmuteCall`). Behavior: stores `CallSid`, returns `CallSession`. Pure HTTP calls to Twilio REST — no streaming yet.
2. **Webhook routes** — `/api/twilio/voice` (returns TwiML `<Dial><Number>{lead.phone}</Number></Dial>` with `record="record-from-answer-dual"`); `/api/twilio/status` (looks up Call by twilioSid, updates DB status); `/api/twilio/recording` (updates `Call.recordingUrl` when Twilio finishes processing).
3. **Token route** — `/api/twilio/token` (server generates JWT for the authenticated agent; scopes: outgoing voice + identity = agent's user id).
4. **Provider selection** — update `index.ts` to switch on `TELEPHONY_PROVIDER` env.
5. **Dialer engine cleanup** — replace `instanceof MockTelephonyProvider` callback wiring with provider-agnostic flow (status updates come from Twilio webhook, not in-process callback).
6. **Dialer UI** — add `Twilio.Device` setup. On `Start Calling`, fetch token, instantiate Device, listen for `incoming/connect/disconnect/error`. On `initiateCall` button, call our `/api/dialer/call` (which returns the lead's phone), then `device.connect({ params: { To: phone } })` — Twilio handshakes via the TwiML app to our `/voice` endpoint.
7. **Tests** — provider tests with mocked Twilio SDK; webhook tests with mocked Prisma.

## Compliance + ops considerations (flagged, not built this phase)

- **TCPA**: business-to-business is generally exempt, but consumer calls need consent. Existing Lead has no consent flag yet — add in a later phase before going wide.
- **DNC check**: should happen in `getNextContact` before dialing. Today: no DNC list infrastructure. Defer to Phase 7 (DNC/Suppression).
- **Recording disclosure**: TwiML can prepend `<Say>` ("this call may be recorded") before `<Dial>`. Add when going live.
- **Caller ID rotation / spam scoring**: single outbound number will get flagged after ~50 calls/day. Future: maintain a pool of numbers and rotate. Defer.
- **Two-way audio quality**: WebRTC over corporate WiFi can be flaky. Test with the actual closers before rollout.
